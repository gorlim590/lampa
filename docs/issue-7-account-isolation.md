# Issue #7: account isolation and snapshot integrity

Based on main a33f4b1 (PR #23 already merged). This follow-up changes only watched integrity and its native GET adapter/tests; YDesign and the recommendation/catalog architecture are unchanged.

## Root causes and boundaries

1. Cache v6 had no account owner. The presence of any access credential allowed a fresh cache to be treated as current, including after switching accounts or restarting. Shared promises/stamps/show-progress jobs likewise outlived authorization changes.
2. `activityStamp({movies:{},episodes:{}})` returned the nonempty string `||||`. Missing and malformed date values could compare equal, allowing Favorite imports and advancing last-success without a verified snapshot.
3. TraktTV's public GET adapter did not expose its existing cache/dedup policy options. Numeric show-progress routes can be cached as metadata, and in-flight request keys use credential suffixes. Integrity reads must bypass these transport caches instead of inheriting an older request.

## Identity and migration

Trakt+ 3.2.1 verifies authenticated `/users/me` (the existing native profile endpoint), preferring `user.ids.uuid` and using the authenticated `user.ids.slug` only as a compatibility fallback. A slug rename causes a safe cold cache, not inferred identity matching. Never infer a user from a token, local History or a previous cache.

Cache v7 records `owner` alongside the verified watched evidence. It is hydrated only after the current authenticated owner has been verified. A missing/legacy/mismatched owner remains unknown until a fresh verified snapshot. The old stored cache is retained on errors and replaced only on valid acceptance. A single latest-owner cache is retained, not an unbounded per-account archive.

Credentials are compared **only in memory** as an authorization-generation change signal; they are not persisted as IDs, hashes, cache keys or logs by Trakt+. Logout/change invalidates memory, promises, stamps, pending progress, manual ownership and last result. Auth changes are observed through one Lampa Storage listener, one cross-document storage listener, and guards at public reads/async boundaries. Same-user rotation briefly returns unknown until identity verification restores its same-owner cache. A sync already crossing a credential boundary may be safely cancelled and retried; it is not allowed to guess the owner.

All identity/watched/progress requests use the existing TraktTV GET transport with cache/dedup disabled through a backward-compatible optional third GET argument. No new HTTP client, tokens or authorization mechanism is introduced. Logical cancellation rejects stale jobs immediately; underlying native HTTP requests may still finish, with their responses discarded. Stale jobs cannot persist cache, import Favorites, unlock a new manual import or emit stale progress updates.

`trakt_plus_last_sync_owner` prevents a recent successful sync of A from suppressing B's automatic sync. Local Favorite/History/Timeline, additive library and provenance remain retained; none are used as watched authority and no automatic removal is introduced.

## Minimum watched activity contract

Primary references: [Trakt API](https://trakt.docs.apiary.io/), [last activity](https://trakt.docs.apiary.io/#reference/sync/last-activities/get-last-activity), [authenticated settings](https://trakt.docs.apiary.io/#reference/users/me/get-settings), [Trakt maintainer explanation of global watched activity](https://github.com/trakt/trakt-api/discussions/473).

The watched verifier requires object containers and nonempty valid UTC ISO timestamps for:

- `all`
- `movies.watched_at`
- `episodes.watched_at`

When `movies.paused_at` or `episodes.paused_at` are supplied they must also be valid UTC timestamps. Unrelated categories are not required for watched completeness. Types, full date/time syntax and calendar components are checked; date-only strings, arrays, null, empty values and normalized-invalid dates such as February 30 are rejected. No invented timestamp substitutes for a missing value. Fractional seconds are optional. The explicit absent optional-field marker is never treated as a timestamp.

Both the initial and final snapshots are validated and compared before any manual import or acceptance of newly read watched evidence. A fresh same-owner unchanged activity stamp may reuse already verified cached evidence, without accepting a new watched payload or advancing last-success. Failures leave the prior disk cache, local data and last-success unchanged, while the public status becomes unknown.

An empty account is represented by valid API timestamps plus empty watched/history lists; no special guessed date or synthetic watched record is generated by production code. The empty-account regression uses explicit fixture dates, not a claim that every real new account uses an epoch date. No live empty account or private API payload was sampled. Direct Apiary page extraction was unavailable during this session; the documented endpoint/UTC contract and maintainer reference are linked for review.

## Validation and limits

- Baseline main reproduced 34 failures among the first 41 new regression cases; the existing 52 checks passed before implementation.
- Final unit/static/runtime results and exact tested commit are recorded in `audit/issue-7-account/` and the Draft PR.
- All account transitions use synthetic isolated data. Real Trakt writes are forbidden and browser requests with mutation methods are blocked.
- Browser desktop tests are not physical Google TV validation. Actual full-account954/911 reconciliation, real login/refresh backend behavior and physical-device performance remain unverified.
- UI unknown-state retention and YDesign display ownership remain Issue #8; this change supplies the correct tri-state API and does not implement those rules.
